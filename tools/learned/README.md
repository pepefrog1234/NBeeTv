# 學習式影像編碼（實驗中）

一個卷積網路把 96×72 的畫面直接變成 7776 個實數（兩個一組當 OFDM 格點的 I、Q，和類比模式 9 用的資源一樣多），
另一個網路把收到的值連同訊雜比還原成畫面。沒有量化也沒有熵編碼，訊號變差時畫質跟著慢慢變差。

這個資料夾是訓練與匯出用的 Python 程式。C++ 的推論在 `core/src/learned_codec.cpp`，權重在 `models/`。

在數據機裡它是**模式 11**（`core/src/learned_frame.cpp`）：幀的安排和類比模式 9 相同，可以用
`nbtv-tx --mode 11`、`nbtv-rx`、`nbtv-sim --mode 11` 收發；外殼透過 C API 的 `nbtv_model_load`、
`nbtv_tx_set_model`、`nbtv_rx_set_model` 把權重交給核心。`nbtv-learned` 則不經過數據機，只看「畫面 ↔ 通道值」這一段。
macOS 的 app 把權重檔放在自己的 Resources 裡，啟動後載入，模式選單裡多一個「學習式 11」。

## 檔案

| 檔案 | 內容 |
| --- | --- |
| `model.py` | 網路的結構（590 萬個參數），以及接收端交給解碼器之前的處理（`receive`）。編碼器不知道對方的訊雜比，解碼器知道 |
| `prep.py` | 把一個資料夾的照片切成 96×72 的小圖，分成訓練用與測試用 |
| `train.py` | 訓練；通道含衰落與缺值；發散時會自動退回上一個好的狀態 |
| `evaluate.py` | 模型在白雜訊、衰落、少掉一部分的值時的 PSNR |
| `export.py` | 檢查點 → C++ 讀的權重檔，以及測試用的參考答案。權重檔的格式寫在檔案開頭 |

## 兩版模型

**結構 1**（`learned_7776_v1`，已經不用）：訓練時一張畫面的每個值雜訊一樣大。白雜訊下沒有問題，但衰落通道下有一大部分的值
等於沒收到——接收端把它們壓到接近 0，解碼器沒見過缺值，就把 0 當成真的資料，在畫面上畫出不存在的東西：
帶點陣的黑塊、拖影，在黑白剪影這種大片純色的畫面上最明顯。實機測試時看到的就是這個。

**結構 2**（`learned_7776_v2`，現在用的）：

- 訓練時的通道含衰落（每個值各自乘上一個隨機的功率增益）、隨機少掉一部分的值、以及接收端估雜訊的誤差；
  訊雜比的範圍往下延伸到 −6 dB。
- 解碼器多一個輸入：每個值的「可靠程度」（0 到 1）。接收端把太吵的值按比例壓小，並把壓了多少告訴解碼器，
  缺的地方它就由周圍補。
- 幀裡的值先照固定的亂數排列打散（`learned_frame.cpp`），一片衰落抹掉的值才會平均分到整張畫面，
  訓練時也才能把每個值當成各自獨立。

接收端的處理（`model.receive`，和 `learned_frame.cpp` 的 `learned_picture` 相同）：取各個值的雜訊變異數 σ² 的中位數當參考值
（夾在解碼器認得的 −6 到 30 dB 之間）告訴解碼器；比參考值吵的值乘上 (1+σ²參考)／(1+σ²)，這個比例就是可靠程度。

## 重新產生權重

需要 PyTorch、NumPy、Pillow。第一版是用 PyTorch 2.8.0（Python 3.9）訓練的，第二版用 2.15.0（Python 3.12）加 `--compile`；
都在 Apple 晶片的 GPU 上。

```sh
# 資料：COCO val2017，5,000 張照片，816 MB
curl -O http://images.cocodataset.org/zips/val2017.zip && unzip -q val2017.zip
python3 prep.py val2017 data          # 4,600 張照片 → 138,000 張訓練小圖；另外 400 張照片 → 800 張測試小圖

# 第一版：只有白雜訊，3 萬步，M4 Max 約 50 分鐘
python3 train.py --arch 1 --train data/train.npy --val data/val.npy --latent 72 --out run1
python3 export.py run1/model.pt v1.bin

# 第二版：從第一版的權重接著訓練 2.4 萬步，約 40 分鐘
python3 train.py --init v1.bin --train data/train.npy --val data/val.npy --latent 72 \
    --steps 24000 --lr 1.5e-4 --warmup 500 --compile --out run2
python3 evaluate.py run2/model.pt data/val.npy
python3 export.py run2/model.pt ../../models/learned_7776_v2.bin \
    --reference ../../core/tests/data/learned_7776_v2_ref.bin \
    ../../core/tests/data/coffee.ppm ../../core/tests/data/rocket.ppm ../../core/tests/data/cat.ppm
```

第一版當時用的是只有白雜訊的訓練程式；現在的 `train.py --arch 1` 是同樣的設定，但沒有重新跑過。

重新訓練出來的權重不會和現在的逐位元相同，識別碼也會不同。換了權重要同時更新
`core/tests/test_learned.cpp` 裡的識別碼與對照的 PSNR；收發兩端也必須一起換
（幀的標頭帶著識別碼的最低 8 位元，兩邊不同時接收端不會交出畫面）。

權重存成 float16（11.8 MB）：第一版在 800 張測試小圖、各訊雜比下的 PSNR 和 float32 到小數第三位都相同。
每個輸出通道各自量化成 int8 可以再小一半，但 PSNR 會掉 0.02–0.14 dB，沒有採用。

已知的弱點：

- 訊雜比很高、沒有衰落時，輸給類比模式 9（不經過數據機時，30 dB 差 0.6 dB、無雜訊差 0.7 dB）。
- 小塊的鮮豔顏色會變淡、色調偏移，沒有雜訊時也一樣。例：一朵粉紅色的花，彩度在原圖是 48，
  類比模式 9（10 dB）是 37，學習式編碼是 25 左右（兩版都一樣）。大面積的顏色沒有這個問題。
- 碎石、細刺這類細紋理會被抹平。
- 帶字幕或文字的畫面遠不如數位模式。

C++ 與 PyTorch 的一致性（結構 2）：三張測試圖的通道值最大相差 4.5×10⁻⁶（均方根是 0.707），解出來的畫面 124,416 個值裡有
6 個差一階。速度（M4 Max，單執行緒）：編碼每張 29 ms、解碼 53 ms。

## 還沒做的與限制

- 還沒有實機驗證第二版：以上都是模擬。第一版在實機上看到的問題（衰落時的黑塊與點陣）在模擬裡重現、也在模擬裡消失了，
  但空中的情形還要再測。macOS 的 app 支援模式 11，只用內附的測試圖驗證過。
- 訓練時的衰落是「每個值各自獨立」，靠幀裡的打散來成立；實際的通道估測誤差、頻率選擇性衰落的細節只在 `nbtv-sim` 裡驗證過。
- 模型小、訓練短（第一版 3 萬步加第二版 2.4 萬步）。訊雜比高時的落後與顏色變淡是不是訓練不足造成的，沒有驗證。
- 訓練資料是 COCO 的照片。COCO 的標註是 CC BY 4.0，照片本身的著作權屬於各拍攝者，各自採用不同的創用 CC 授權
  （有些限非商業使用）。散布用它訓練出來的權重之前，要先確認這一點。
