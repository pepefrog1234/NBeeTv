# 學習式影像編碼（實驗中）

一個卷積網路把 96×72 的畫面直接變成一串實數（兩個一組當 OFDM 格點的 I、Q），另一個網路把收到的值連同訊雜比還原成畫面。
沒有量化也沒有熵編碼，訊號變差時畫質跟著慢慢變差。

這個資料夾是訓練與匯出用的 Python 程式。C++ 的推論在 `core/src/learned_codec.cpp`，權重在 `models/`。

數據機裡有兩個學習式模式（`core/src/learned_frame.cpp`），幀的安排各比照一個類比模式，用的時間與格點一樣多：

| 模式 | 每張 | 幀比照 | 一張畫面的實數 | 潛在通道數 | 權重檔 |
| --- | --- | --- | --- | --- | --- |
| 11 | 2.72 秒 | 類比模式 9 | 7776 | 72 | `models/learned_7776_v2.bin` |
| 12 | 1.04 秒 | 類比模式 8 | 2592 | 24 | `models/learned_2592_v2.bin` |

兩個模型的結構相同，只差瓶頸（潛在張量）的通道數。核心依「模型的實數個數和模式的相同」決定哪個模型給哪個模式用，
發射機與接收機可以同時掛兩個。用 `nbtv-tx --mode 11`（或 12）、`nbtv-rx`、`nbtv-sim --mode 11` 收發；
外殼透過 C API 的 `nbtv_model_load`、`nbtv_tx_set_model`、`nbtv_rx_set_model` 把權重交給核心（每個模型各設定一次）。
`nbtv-learned` 則不經過數據機，只看「畫面 ↔ 通道值」這一段。
macOS 的 app 把兩份權重檔放在自己的 Resources 裡，啟動後載入，模式選單裡多一組「學習式」。

## 檔案

| 檔案 | 內容 |
| --- | --- |
| `model.py` | 網路的結構（590 萬個參數），以及接收端交給解碼器之前的處理（`receive`）。編碼器不知道對方的訊雜比，解碼器知道 |
| `prep.py` | 把一個資料夾的照片切成 96×72 的小圖，分成訓練用與測試用 |
| `train.py` | 訓練；通道含衰落與缺值；發散時會自動退回上一個好的狀態 |
| `evaluate.py` | 模型在白雜訊、衰落、少掉一部分的值時的 PSNR |
| `export.py` | 檢查點 → C++ 讀的權重檔，以及測試用的參考答案。權重檔的格式寫在檔案開頭 |

## 兩版模型

**結構 1**（`learned_7776_v1`，已經不用）：訓練時一張畫面的每個值雜訊一樣大。白雜訊下沒有問題，但衰落通道下有一大部分的值
等於沒收到——接收端把它們壓到接近 0，解碼器沒見過缺值，就把 0 當成真的資料，在畫面上畫出不存在的東西：
帶點陣的黑塊、拖影，在黑白剪影這種大片純色的畫面上最明顯。實機測試時看到的就是這個。

**結構 2**（`learned_7776_v2` 與 `learned_2592_v2`，現在用的）：

- 訓練時的通道含衰落（每個值各自乘上一個隨機的功率增益）、隨機少掉一部分的值、以及接收端估雜訊的誤差；
  訊雜比的範圍往下延伸到 −6 dB。
- 解碼器多一個輸入：每個值的「可靠程度」（0 到 1）。接收端把太吵的值按比例壓小，並把壓了多少告訴解碼器，
  缺的地方它就由周圍補。
- 幀裡的值先照固定的亂數排列打散（`learned_frame.cpp`），一片衰落抹掉的值才會平均分到整張畫面，
  訓練時也才能把每個值當成各自獨立。

接收端的處理（`model.receive`，和 `learned_frame.cpp` 的 `learned_picture` 相同）：取各個值的雜訊變異數 σ² 的中位數當參考值
（夾在解碼器認得的 −6 到 30 dB 之間）告訴解碼器；比參考值吵的值乘上 (1+σ²參考)／(1+σ²)，這個比例就是可靠程度。

## 重新產生權重

需要 PyTorch、NumPy、Pillow。第一版是用 PyTorch 2.8.0（Python 3.9）訓練的，第二版用 2.15.0（Python 3.12）加 `--compile`；
都在 Apple 晶片的 GPU 上。

```sh
# 資料：COCO val2017，5,000 張照片，816 MB
curl -O http://images.cocodataset.org/zips/val2017.zip && unzip -q val2017.zip
python3 prep.py val2017 data          # 4,600 張照片 → 138,000 張訓練小圖；另外 400 張照片 → 800 張測試小圖

# 第一版：只有白雜訊，3 萬步，M4 Max 約 50 分鐘
python3 train.py --arch 1 --train data/train.npy --val data/val.npy --latent 72 --out run1
python3 export.py run1/model.pt v1.bin

# 第二版（模式 11 用的）：從第一版的權重接著訓練 2.4 萬步，約 40 分鐘
python3 train.py --init v1.bin --train data/train.npy --val data/val.npy --latent 72 \
    --steps 24000 --lr 1.5e-4 --warmup 500 --compile --out run2
python3 evaluate.py run2/model.pt data/val.npy
python3 export.py run2/model.pt ../../models/learned_7776_v2.bin \
    --reference ../../core/tests/data/learned_7776_v2_ref.bin \
    ../../core/tests/data/coffee.ppm ../../core/tests/data/rocket.ppm ../../core/tests/data/cat.ppm

# 模式 12 用的（潛在通道 24 個）：從模式 11 的權重接著訓練 4 萬步，約 65 分鐘。
# 瓶頸兩側的三個張量（enc.head 的權重與偏差、dec.inp 的權重）形狀不同，從頭學；其餘的照搬。
python3 train.py --init ../../models/learned_7776_v2.bin --train data/train.npy --val data/val.npy --latent 24 \
    --steps 40000 --compile --out run12
python3 evaluate.py run12/model.pt data/val.npy
python3 export.py run12/model.pt ../../models/learned_2592_v2.bin \
    --reference ../../core/tests/data/learned_2592_v2_ref.bin \
    ../../core/tests/data/coffee.ppm ../../core/tests/data/rocket.ppm ../../core/tests/data/cat.ppm
```

第一版當時用的是只有白雜訊的訓練程式；現在的 `train.py --arch 1` 是同樣的設定，但沒有重新跑過。

重新訓練出來的權重不會和現在的逐位元相同，識別碼也會不同。換了權重要同時更新
`core/tests/test_learned.cpp` 裡的識別碼與對照的 PSNR；收發兩端也必須一起換
（幀的標頭帶著識別碼的最低 8 位元，兩邊不同時接收端不會交出畫面）。

權重存成 float16（兩份各約 11.8 MB）：第一版在 800 張測試小圖、各訊雜比下的 PSNR 和 float32 到小數第三位都相同。
每個輸出通道各自量化成 int8 可以再小一半，但 PSNR 會掉 0.02–0.14 dB，沒有採用。

- 細節比模式 11 少：每個 8×8 的區塊只有 24 個實數可用，細紋理被抹平。
- 文字會被抹糊。類比模式 8 雖然滿是雜點，大字反而比較認得出來：一張購物網頁的截圖過差通道、5 dB 時，
  上面的價格在模式 8 還勉強讀得出來，在模式 12 讀不出來（15 dB 時兩者都大致讀得出來）。只看了這一張。
- 小塊的鮮豔顏色會變淡，程度和類比模式 8 差不多：一張開花的仙人掌，原圖裡彩度最高的 3% 像素平均彩度是 41.5，
  沒有雜訊、經過完整的收發鏈之後，模式 12 是 31.2、類比模式 8 是 30.7（模式 11 是 34.9、類比模式 9 是 37.1）。
- 訊雜比掉到 −3 dB 以下、或一半以上的值沒收到時，畫質掉得比模式 11 快：黑白剪影在 −6 dB 的白雜訊下只剩 15.0 dB
  （模式 11 的模型是 21.3 dB）。
- 一片衰落抹掉的值分到每個位置只有 24 個通道，各個位置受損的程度差異比模式 11 大
  （抹掉一成的值時，各位置少掉的通道在 0% 到 25% 之間；模式 11 是 1% 到 19%）。

### C++ 與 PyTorch 的一致性

三張測試圖的通道值（均方根是 0.707）最大相差：模式 11 的模型 4.5×10⁻⁶、模式 12 的模型 2.4×10⁻⁶；解出來的畫面 124,416 個值裡
各有 6 個差一階。速度（M4 Max，單執行緒）：兩個模型都是編碼每張約 30 ms、解碼約 55 ms（差別只在瓶頸兩側的兩層）。

## 還沒做的與限制

- 還沒有實機驗證模式 11 的第二版與模式 12：以上都是模擬。第一版在實機上看到的問題（衰落時的黑塊與點陣）在模擬裡重現、
  也在模擬裡消失了，但空中的情形還要再測。macOS 的 app 支援模式 11 與 12，只用內附的測試圖驗證過。
- 訓練時的衰落是「每個值各自獨立」，靠幀裡的打散來成立；實際的通道估測誤差、頻率選擇性衰落的細節只在 `nbtv-sim` 裡驗證過。
- 模型小、訓練短（模式 11：第一版 3 萬步加第二版 2.4 萬步；模式 12：接著再 4 萬步）。訊雜比高時的落後與顏色變淡
  是不是模型太小或訓練不足造成的，沒有驗證。
