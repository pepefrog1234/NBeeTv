# macOS 外殼

SwiftUI 寫的 macOS app。音訊裝置、鏡頭、影片檔、圖片序列、PTT 與介面都在這裡；調變解調、畫面的編解碼（類神經網路）全部交給核心，
而且只透過 `core/include/nbtv/nbtv.h` 這一個 C API 使用核心（經由 `CNBTV/` 的 module map 匯入 Swift）。
介面照 [macOS 介面版面](../../短波%20NBTV%20macOS%20介面版面.html) 的五張版面做；
頂列的「定時發射」鈕與它的面板是後來加的，版面稿裡沒有。

## 建置

需要 Xcode（Swift 編譯器與 macOS SDK）、CMake、Ninja。核心不需要其他函式庫。

```sh
cmake -S . -B build-app -G Ninja -DNBTV_BUILD_MACOS_APP=ON -DNBTV_BUILD_TESTS=OFF -DNBTV_BUILD_TOOLS=OFF
cmake --build build-app
```

產物是 `build-app/apps/macos/NBTV.app`。建置的最後一步會把內附的測試圖、各個模式的模型權重檔（九份）與合併最近幾幀用的權重（都在 `models/`）複製進 bundle，並做 ad-hoc 簽章
（系統的相機與麥克風權限要 bundle 有簽章才認得）。沒有開沙盒。

- CMake 的 Swift 支援只有 Ninja 與 Xcode 兩種產生器能用，所以這個目錄要另外用 `-G Ninja` 設定。
- 最低系統版本：程式只用到 macOS 14 就有的 API。要做出能在 macOS 14 執行的版本，設定時加上
  `-DCMAKE_OSX_DEPLOYMENT_TARGET=14.0`（這裡會把它轉成 swiftc 的 `-target`；CMake 自己不會轉）。
  不指定時，以建置這台機器的系統版本為準。
- ad-hoc 簽章每次重新建置都會變，系統可能會再問一次相機與麥克風的權限。

### 發佈用的簽章與公證

建置出來的 app 只有 ad-hoc 簽章，別人從網路下載之後會被 macOS 擋下來。要給人下載的版本另外用
[`sign-and-notarize.sh`](sign-and-notarize.sh) 處理：用 Developer ID Application 憑證重新簽章（開 Hardened Runtime、帶安全時間戳記；
權限宣告在 [`NBTV.entitlements`](NBTV.entitlements)，只有鏡頭與音訊輸入兩項）、送 Apple 公證、把票據釘在 app 上，再壓成 zip。
簽的是複製出來的那一份，建置目錄裡的 app 不會被改到。

```sh
NBTV_SIGN_IDENTITY="Developer ID Application: 名稱 (Team ID)" NBTV_NOTARY_PROFILE=設定檔名稱 \
  apps/macos/sign-and-notarize.sh build-app/apps/macos/NBTV.app NBTV-app.zip
```

- 需要付費的 Apple Developer Program 會員資格，以及一張連同私鑰都在鑰匙圈裡的 Developer ID Application 憑證。
- 公證的登入資料先存進鑰匙圈：`xcrun notarytool store-credentials 設定檔名稱 --apple-id … --team-id …`（它會問 App 專用密碼）。
  這個設定檔在螢幕鎖定時讀不到（`notarytool` 會說找不到它），要在解鎖的狀態下執行。
  也可以改用 App Store Connect 的 API 金鑰；用哪些環境變數寫在指令稿的開頭。
- GitHub 上推版本標籤時，CI 的 `sign-macos` 工作對兩種處理器的 app 各做一次，發佈頁放的是簽過的那兩份。
  憑證與登入資料放在 repo 的 `release-signing` 這個 Environment 的 secrets 裡，名稱列在 `.github/workflows/build.yml` 那個工作的說明；
  沒有設定時那個工作什麼都不做，發佈的仍然是 ad-hoc 簽章的。手動執行那份流程並勾選 sign，可以只試簽章與公證、不發佈；
  再填上 reuse_run（先前某一次執行的編號），就不重新建置，直接拿那一次做好的 app 來簽，幾分鐘就有結果。
- 憑證上的名稱（個人會員是法定姓名）會留在每一份簽過的 app 裡，用 `codesign -dv` 看得到。
- 沒有開沙盒，也沒有用到別的 Hardened Runtime 例外。以後 bundle 裡如果加了內嵌的程式或程式庫，要先由內而外各自簽過，指令稿要跟著改。
- 2026-11-27 在開發用的 Mac 上實際走過：簽章、公證（從上傳到通過約一分鐘）、釘票據之後，Gatekeeper 的評估是「Notarized Developer ID」，
  簽過的那一份跑 `--selftest --no-devices` 沒有失敗的項目。**還沒有驗證的**：CI 上的 `sign-macos` 還沒有實際跑過；
  Hardened Runtime 下實際開鏡頭與收音；下載之後第一次開啟時系統顯示的畫面。

## 執行

```sh
open build-app/apps/macos/NBTV.app
```

第一次使用：

1. 按右上角的齒輪（或 ⌘,）打開設定，填呼號、選音訊的輸入與輸出裝置、選 PTT 的控制方式。
   沒有填呼號不能發射。
2. 系統會問麥克風權限（接收要從音訊輸入裝置收音），選鏡頭當發射來源時會問相機權限。
3. 回到主視窗就已經在接收了。右側欄選發射來源（鏡頭、影片檔或圖片序列）、縮放方式與發射模式，按「開始發射」。

### 介面的語言

介面有五種語言：繁體中文（台灣的電腦用語）、簡體中文（中國的電腦用語）、日文、西班牙文、美式英文。
啟動時自動照系統的語言顯示，不必設定：

- 用的是「系統設定 → 一般 → 語言與地區」的語言清單裡，排最前面、而且這個 app 有翻譯的那一個；清單裡一個都沒有翻譯的話用英文
  （例如系統是法文、德文、韓文時顯示英文；清單是「法文、日文」時顯示日文——這是 macOS 替每個 app 挑語言的規則）。
  香港、澳門的繁體中文用繁體中文那一份，新加坡的簡體中文用簡體中文那一份；各地的西班牙文、英文各用同一份。
- 也可以只替這個 app 指定語言：「系統設定 → 一般 → 語言與地區 → 應用程式」。
- 系統自己畫的部分（功能表列、開檔與存檔的對話框、詢問麥克風與相機權限時的說明）跟著同一種語言。
- 不翻譯的東西：呼號、裝置名稱（系統給的）、Hamlib 的電台型號、畫布上印的字、存檔的檔名；
  數字一律用小數點（西班牙文也是 2.72 s）；開發用的輸出（`--selftest`、`--snapshot`、除錯紀錄）一律是繁體中文。

翻譯放在 `Localization/<語言>.lproj/`：`Localizable.strings` 是介面的每一句，`InfoPlist.strings` 是 app 的名稱與權限的說明。
原始碼裡給使用者看的每一句都寫成 `L("繁體中文原文", 值…)`，原文同時是索引（所以繁體中文不需要翻譯表），
`Localizable.strings` 每一行是 `"原文" = "翻譯";`。句子裡要填的值用 `%@`、`%d` 這類記號，翻譯可以用 `%1$@`、`%2$d` 調換順序；
數量剛好是 1 時的說法另外寫一行 `"原文#1"`（英文、西班牙文的單數）。

- 改了介面的文字、或要補翻譯：改完執行 `python3 apps/macos/Localization/check_strings.py`，它會對著原始碼列出漏翻的、多餘的、
  要填的值對不上的。建置時也會跑一次（找得到 `python3` 的話），有問題就建不過。
- 要多一種語言：加一個 `<語言>.lproj`（兩個檔案），再把語言代碼加進 `CMakeLists.txt` 的 `NBTV_APP_LANGUAGES`、
  `Sources/Localization.swift` 的 `L10n.languages` 與 `check_strings.py` 的 `LANGUAGES`。
- 簡體中文、日文、西班牙文、英文的翻譯是寫程式的時候一起寫的，沒有請以這些語言為母語的業餘無線電玩家看過；
  用語（例如日文的「送信／受信／コールサイン」、西班牙文的「indicativo／equipo」、簡體中文的「串口／波特率／摄像头」）如果不合習慣，直接改那一份 `.strings` 就好。

### 同一台電腦上同時開兩個

兩部電台接在同一台電腦上、要互相收發時，需要兩個設定各自獨立的 app。設定建置目錄時加上
`-DNBTV_MACOS_SECOND_APP=ON`，建置就會多做出 `NBTV 2.app`：

```sh
cmake -S . -B build-app -G Ninja -DNBTV_BUILD_MACOS_APP=ON -DNBTV_MACOS_SECOND_APP=ON -DNBTV_BUILD_TESTS=OFF -DNBTV_BUILD_TOOLS=OFF
cmake --build build-app
open "build-app/apps/macos/NBTV 2.app"
```

- `NBTV 2.app` 是 `NBTV.app` 的複本：程式完全相同，只有名稱與 bundle 識別碼不同（`tw.hf-nbtv.mac2`）。
  每次建置都會跟著重做，所以兩個一定是同一版。
- 識別碼不同，呼號、音訊裝置、PTT 等設定就各存各的；系統的麥克風與相機權限也要各自同意一次。
- 主視窗頂列的名稱是「短波 NBTV 2」，設定視窗的標題是「設定 — 短波 NBTV 2」，用來分辨眼前是哪一個。
- 兩個 app 各接一部電台：各選各的輸入裝置、輸出裝置與 PTT，兩邊不要選同一個序列埠。
- 第一次開啟時兩個視窗的位置相同，第二個會剛好蓋住第一個，拖開即可（之後各自記得位置）。

### 接上電台之前

還沒有實機測試過。下面是從訊號的設計推出來的注意事項：

- 訊號佔 352–2648 Hz。收發兩邊都用 USB（或資料模式），發射與接收的濾波器都要涵蓋這一段；
  比它窄的濾波器會切掉邊緣的子載波。
- 兩部電台的頻率差要在 ±150 Hz 以內，超過就同步不到。
- 關掉會改變波形的處理：發射端的語音壓縮與等化，接收端的降噪（NR）與自動陷波（導頻是固定的載波，會被當成干擾濾掉）。
- OFDM 的峰值比平均高很多。輸出音量調到 ALC 不動作為止，平均功率會比額定功率低不少，這是正常的。
  輸出音量的滑桿在主視窗右側欄、發射鈕的上面：發射中一邊看電台的 ALC 一邊拉，改了立刻生效。
- 兩部電台放在一起時訊號很強，接收端容易過載失真；用假負載、最小功率或衰減器。

收發的流程：

- **接收**：音訊一進來就交給核心；模式自動偵測。收到的畫面排在「最近收到」，點縮圖可以換到主畫面；
  之後只要有新的畫面進來，主畫面就換成新的那一張（點選只維持到下一張進來為止，原來那一張還在「最近收到」裡）。
  「儲存圖片」把主畫面那一張存成 PNG，大小和收到的畫面相同（96×72，模式 4–7 與 15 是 192×144），像素完全相同。
  「儲存影片」把主畫面那一張所在的**一段**串成影片檔：.mp4、H.264、每秒 24 格、960×720（每個像素放大成 10×10，不內插）。
  一段是同一個呼號、一張接一張收到的畫面，兩張之間的空檔不到 10 秒（空檔是前一張收完到後一張開始送之間的時間，
  連續發射時是 0，中間漏掉一張時是一張的長度）；標頭沒解出來、不知道呼號的畫面，時間接得上就跟著前面那一段。
  按鈕上寫著這一段有幾張，只有一張時不能按。影片裡每一張顯示到下一張收到為止，快慢和當時收到的一樣，最後一張停留一張的時間。
  存檔的對話框下方有一個選項「在每一張的左上角印上訊雜比」：勾了之後，影片裡每一張的左上角印著收到它當下的訊雜比
  （「SNR 12.3 dB」，白字、半透明的黑底，樣子和主畫面上疊的標示一樣，字大一點，縮小了看也認得出來）。
  勾不勾會記住，下一次存影片時沿用；預設是不印。
  收發兩邊的模型要是同一份；對方用的是另一份權重時，狀態顯示「模型不符」、沒有畫面。
  「最近收到」一次看得到六張（三張一列、兩列），更早的在那一塊裡往下捲；最多留 5000 張，再多就丟掉最舊的。
  設定裡的「在收到的畫面上標示訊雜比」打開之後，主畫面與每張縮圖的左上角會標出收到那一張當下接收機量到的訊雜比
  （只是疊在畫面上顯示，存檔的圖片裡沒有；存成影片時要不要印是另一個選項，在存影片的對話框裡，見上面）。
  接收時固定會「合併最近幾幀」（原本是設定裡的選項，預設就是開的；2026-11-25 起固定開著，設定裡不再有這一項）：
  解每一張之前，畫面沒變的地方把前面 3 張收到的值合進來，訊號弱、畫面平靜時比較清楚；
  訊號好或畫面一直在變時和不合併幾乎一樣。只在接收端處理，對方不需要設定。四個模式都有；
  按「開始接收」時會忘掉前面的幀。做法與量到的效果見 `tools/learned/README.md` 的「接收端合併最近幾幀」。
- **發射**：按下後先按 PTT，等 0.3 秒才開始送音訊；每一張都在前一張快送完時才取來源當下的那一格，
  幀與幀之間沒有空隙。「快送完」至少是剩 0.6 秒；大型網路的模式（13、14）編碼加預覽比較花時間（這台開發機約 0.3 秒），
  app 會照實際花的時間自動提早。發射中接收暫停、不能換模式，但可以換來源與縮放方式（下一張生效）。
  按「停止發射」後送完目前這一張，補上尾巴，放開 PTT，回到接收。
- **畫布**：右側欄的「畫布」打開之後，送出去的每一張畫面上都印一行字（例如「CQ BX4ACP」；第一次打開而還沒有填字時，
  先填上「CQ 呼號」），印在畫面的上緣或下緣。字是白的，底下墊一條半透明的黑帶；字盡量大（最大 18 個像素高的字級），
  一行放不下就縮小，縮到 12 以下還放不下就在空白處拆成兩行（兩行時字級最大 12，字帶約佔畫面的三分之一），再放不下的結尾截成「…」。最多 40 個字。
  右側欄的預覽就是印好字、會送出去的樣子；發射中改了字，下一張就照新的印。鏡頭、影片檔、圖片序列三種來源與定時發射都會印。
  輸入框平常不接鍵盤（視窗一打開不會自己跳進去），要用滑鼠點進去才打得了字；按 Return 就離開。
- **用影片檔發射**：開始送音訊的同時影片自動開始播放（已經在播的不動；停在結尾的先回到開頭）。
  按下「停止發射」的當下影片就跟著暫停（從這時起不會再取新的畫面），下一次發射從停下的地方接著播；
  送到一半出錯而中止時也一樣。還沒開始送音訊就取消的，影片維持原來的樣子。
  沒有勾「循環播放」時，影片開了之後停在開頭等著，按下發射才開始播；播完之後再送出它的最後一格，
  然後和按下停止一樣收尾、放開 PTT、回到接收，所以發射結束的時間會比影片的結尾晚一到兩張。
  勾了「循環播放」時影片一開就播、播完從頭再來，發射要自己按停止。發射中可以隨時按停止。
- **用圖片序列發射**：發射來源選「圖片序列」，按「選擇…」挑要送的圖片：可以一次選很多張，也可以選資料夾
  （裡面的圖片全部加入；只看那一層，不往子資料夾裡找）。系統讀得進來的圖片都可以（JPEG、PNG、HEIC、TIFF、GIF、WebP、
  各家相機的 RAW…；動畫或多頁的檔案只取第一格），手機直拍的相片會照檔案裡記載的方向轉正。
  - **順序照檔名**，和 Finder 用名稱排序時一樣：數字照大小排（`2.jpg` 在 `10.jpg` 前面），不分大小寫。
    在對話框裡先點哪一張、後點哪一張不影響順序；要換順序請改檔名。
  - 預覽是**下一張要送的**那一張，上面的框裡寫著它的檔名。預覽下面可以按「上一張」「下一張」，或拖滑桿跳到第幾張，
    旁邊寫著「第幾張 / 共幾張」。縮放方式與畫布照常套用，預覽就是送出去的樣子。
  - 按下發射之後，從預覽的那一張開始，照順序每一張圖片送一次（一張圖片就是一幀）。
    沒有勾「循環播放」（預設）時，最後一張送完就和按下停止一樣收尾、放開 PTT、回到接收，位置回到第一張；
    勾了就接著從第一張再來，要自己按停止。圖片序列的「循環播放」和影片檔的是分開的兩個設定。
  - 送到一半按「停止發射」：正在送的這一張送完才停，下一次發射從還沒送出去的那一張接著送。
    這時下一張通常已經取走、編好了，它會退回去，不會被跳過；再按一次立刻停止的話，被切掉的那一張下一次重送。
    還沒開始送音訊就取消的，第一張也不算送過。發射中可以換位置、換一批圖片，下一張生效。
  - 讀不到的檔案（壞掉、已經不在）輪到它的時候從序列裡拿掉，底列寫出是哪一個，其餘的照送；後面都讀不到了就停止發射。
  - 選的那一批會記住，下次啟動時自動帶回來（已經不在的檔案略過）；位置不記，每次從第一張開始。
    定時發射播的仍然是影片檔（到時間時來源是圖片序列的話，和鏡頭一樣先換成影片檔，播完再換回來）。
- **定時發射**：頂列右邊的「定時發射」鈕打開面板，勾了「開啟定時發射」之後，每到時鐘上對齊整點的時刻
  （每隔 5、10、15、20、30 或 60 分鐘；每 15 分鐘就是每小時的 00、15、30、45 分整），就自動把影片檔從頭發射一次，
  播完自動停止，不管有沒有勾「循環播放」。播的是「發射來源」裡選的那個影片檔，面板裡也可以選；發射模式用當時選的那一個。
  到時間時來源是鏡頭（或圖片序列）的話，先換成影片檔，播完再換回原來的來源。開著的時候按鈕是橘色的，寫著下一次的時刻，最後一分鐘改成倒數。
  - 下面幾種情形那一次不發射，原因寫在底列與面板的「上一次」：正在發射（自己按的，或上一次的影片比間隔還長）、
    還沒設定呼號、還沒選影片、正在收別人的畫面（接收機同步著，或 3 秒內還同步著；這一項可以在面板裡關掉）、
    到了時間卻晚了 5 秒以上才輪到（電腦剛從睡眠醒來、時鐘被調整過）。錯過的不補發。
  - 從時刻到開始送出訊號大約半秒：取畫面、編碼、按下 PTT，再等 0.3 秒。
  - 定時發射的那一次最多送「影片的長度＋兩張＋5 秒」，超過就和按下停止一樣收尾。正常是影片播完再送一到兩張就結束；
    這個上限是給影片卡住、或發射中來源被換掉的時候用的，旁邊沒有人也收得了尾。發射中可以照常按「停止發射」，下一次照樣會來。
  - 開關不會記住：每次開 app 都是關的，要自己再打開，重開之後才不會在沒有人注意的時候自己發射。
    間隔、「正在收別人的畫面時不發射」與上次選的影片檔會記住，影片檔下次啟動時自動開啟。
  - 開著的時候 app 向系統宣告不要因為閒置而睡眠（螢幕照常可以關）。蓋上筆電或自己選「睡眠」的那段時間不會發射。
  - 到了時間就發射，不會先聽頻率上有沒有別種訊號（認得出來的只有這個 app 自己的訊號）。
    頻率能不能這樣用、可不可以沒有人在旁邊，要自己確認。
- **PTT**：不控制（電台的 VOX）、序列埠的 RTS 或 DTR、電台的 CAT 指令（經序列埠）、Hamlib 的 rigctld（TCP，`T 1`／`T 0`）。
  PTT 出錯時訊息顯示在視窗底列，並回到接收。結束 app 時也會放開 PTT。
  - **不讓 PTT 一直按著的幾道保險**：
    - 發射中音訊輸出裝置不再來取聲音（USB 音效卡斷線、系統的音訊服務卡住）超過 3 秒：自動停止發射、放開 PTT，底列寫出原因。
      發射的每一步都是照「已經播到哪裡」在走的，沒有這一道的話，裝置一停，發射就永遠結束不了。
    - 按了停止之後是「送完目前這張」才停；等不及的話再按一次發射鈕，立刻停止（這一張不完整，對方解不出來）。
      半秒內連按兩下的不算，免得不小心把最後一張切掉。
    - 電腦要睡眠（蓋上筆電、選「睡眠」）時立刻停止發射，等 PTT 放開了才讓系統睡。睡著之後音訊就停了，
      但用指令按下的 PTT 不會自己放開。
    - PTT 的指令說不準有沒有放開時（放開失敗；或按下的指令沒有得到確認、之後補送的放開也沒成功），主畫面上方會疊一條
      橘色的警告要你去看電台，按了「知道了」才消失，而不是只在底列寫一行。（不用系統的對話框：它開著的時候主視窗的按鈕都按不了，
      app 也結束不了。）
  - **電台的 CAT 指令**：在設定裡選電台型號（這台電腦上的 Hamlib 支援的那些，依廠牌分組的選單）、序列埠與序列速率
    （「依型號的預設」是 Hamlib 替那個型號定的，通常是它支援的最高速率；要和電台選單裡的 CAT 速率相同）。
    各廠牌的指令由 Hamlib 翻譯：按下 PTT 時 app 在背景啟動一個只給自己用的 `rigctld`（只聽本機的一個臨時連接埠），
    對它送 `T 1`；放開時送 `T 0`，再把它結束，序列埠跟著還回去。所以這台電腦要先裝 Hamlib
    （`brew install hamlib`；app 會在 `/opt/homebrew/bin`、`/usr/local/bin`、`/opt/local/bin`、`/usr/bin` 與 `PATH` 裡找 `rigctl`、`rigctld`），
    沒有裝的話選單是空的，發射時底列會寫找不到 rigctld。原本的「Hamlib rigctld（TCP）」留著，給自己另外開 rigctld 的人用。
  - 用 CAT 指令時，序列埠的 RTS、DTR 會保持低電位（很多介面拿其中一條當 PTT 或 CW 鍵，序列埠一開它們預設是高的，
    不壓下來的話電台會一直發射）；要用 RTS／CTS 做流量控制的型號，RTS 交給 Hamlib 管。
  - 用指令按下的 PTT 不會因為 app 不在了就自己放開，所以 app 另外帶著一個看門的小程序：app 當掉或被強制結束時，
    它會替 app 送 `T 0`、結束 rigctld。
  - `T 1` 沒有得到確認（電台回報失敗，或三秒沒有回覆）時，指令可能其實已經到了電台，所以回報失敗、收掉 rigctld 之前
    先補送一次 `T 0`。`T 0` 失敗時也再補送一次。
  - 電台沒有回應（型號、序列埠或速率不對，或電台沒開）時，rigctld 自己要重試幾秒才放棄；按下發射之後大約 5 到 15 秒，
    底列才會寫出開不了電台的原因，這段時間狀態是「準備發射」。
- **音訊**：app 與核心之間一律是 48 kHz 單聲道。輸入裝置不是 48 kHz 時在 app 裡轉換，輸出則交給系統轉換；
  輸入只取第一個聲道，立體聲的輸出裝置兩個聲道送一樣的訊號。
- **在背景執行**：app 執行期間會向系統宣告自己在做即時的工作（`ProcessInfo.beginActivity`），
  用意是視窗被蓋住、隱藏或縮進 Dock 時，不要被系統當成閒置而拖慢計時器（App Nap）、來不及取走收到的音訊。

| 環境變數 | 作用 |
| --- | --- |
| `NBTV_DEBUG_SETTINGS="鍵=值;…"` | 用暫時的設定啟動，不讀也不寫使用者的設定。鍵：`callsign`、`input`、`output`（裝置名稱的一部分）、`ptt`（`none`／`serial`／`cat`／`rigctld`）、`rig`（主機:連接埠）、`rigmodel`（用 CAT 指令時的電台型號，Hamlib 的編號；`1` 是不接電台的示範機）、`baud`（CAT 的序列速率，`0` 是預設）、`mode`、`source`（`camera`／`video`／`images`）、`loop`（`0`／`1`，影片循環播放）、`loopimages`（`0`／`1`，圖片序列循環播放）、`snr`（`0`／`1`，在收到的畫面上標示訊雜比）、`stampsnr`（`0`／`1`，存成影片時在每一張的左上角印上訊雜比）、`volume`（輸出音量，dB）、`canvas`（畫布要印的字；給了就打開畫布）、`canvaspos`（`top`／`bottom`）、`every`（定時發射每隔幾分鐘）、`busy`（`0`／`1`，定時發射遇到正在收畫面時不發射）。 |
| `NBTV_DEBUG_VIDEO=<影片檔>` | 啟動後開啟這個影片檔當發射來源。 |
| `NBTV_DEBUG_IMAGES=<資料夾或圖片檔>` | 啟動後把它（資料夾的話是裡面的圖片）當成圖片序列，並印出照順序的檔名；不會記到設定裡。 |
| `NBTV_DEBUG_SIMULATED_OUTPUT=1` | 發射時不開音訊輸出裝置：取樣由模擬的輸出照實際的時間取走、丟掉，不會真的送出聲音。配合 `NBTV_NO_DEVICES=1` 與 `ptt=none`（或 `ptt=cat;rigmodel=1`，Hamlib 不接電台的示範機），可以在真的視窗裡走完整的發射流程而不碰任何裝置。寫成 `stall=秒數` 的話，模擬的輸出取了這麼多秒之後就不再取，用來重現輸出裝置在發射中沒有回應。 |
| `NBTV_DEBUG_SCRIPT="秒:動作;…"` | 主視窗出現後照時間表執行動作，並印出收發流程的轉折。動作有 `tx`、`stop`、`toggle`、`input=`、`output=`、`source=`、`image=n`（圖片序列：下一張要送的改成第 n 張）、`mode=`、`scale=`、`settings`、`modes`、`schedule=on|off|menu`（打開、關掉定時發射，或打開它的面板）、`receive=n`（假裝剛剛連續收到 n 張：內附的測試圖真的經過核心編碼、解碼一次，不必有訊號就能看「最近收到」與存影片）、`select=`、`resize=`、`click=x,y[,視窗]`、`drag=x1,y1,x2,y2[,視窗]`（把滑鼠事件放進 app 的事件佇列）、`type=文字`（把字交給目前接鍵盤輸入的視圖，`\n` 是 Return）、`canvas=文字`、`volume=dB`、`willsleep`（送出「電腦即將睡眠」的通知，電腦不會真的睡）、`savevideo`、`savepanel`（印出開著的存檔或開檔對話框的預設檔名、存影片的對話框裡「印上訊雜比」勾了沒有，然後按取消；寫成 `savepanel=stamp` 的話先按一下那個選項）、`dump`（也會印出鍵盤輸入在不在輸入框裡）、`quit`，說明在 `Sources/NBTVApp.swift` 的 `DebugOptions`。印出來的第一行是起算那一刻時鐘上的時間。 |
| `NBTV_DEBUG_DUMP=<目錄>` | `dump` 動作把每個視窗（連同標題列的控制鈕）存成 PNG 的地方；沒有設就只印狀態。 |
| `NBTV_LANGUAGE=語言` | 這個 app 自己的文字改用指定的語言（`zh-Hant`、`zh-Hans`、`ja`、`es`、`en`），不看系統的語言；系統畫的功能表與對話框不受影響。要整個 app（含系統畫的部分）都換語言，在啟動的參數後面加 `-AppleLanguages "(es)"`，這和在系統設定裡替這個 app 指定語言是同一條路。`dump` 動作會印出目前用的語言與功能表列的每一項。 |
| `NBTV_NO_DEVICES=1` | 啟動時不開音訊輸入、也不開發射來源，之後也不會開鏡頭（上次選的影片檔照常開啟）。發射時還是會開音訊輸出裝置，除非另外設了 `NBTV_DEBUG_SIMULATED_OUTPUT`。 |

例：兩個行程經 BlackHole 對傳，一個發射、一個接收。

```sh
APP=build-app/apps/macos/NBTV.app/Contents/MacOS/NBTV
$APP --receive-test --device BlackHole --seconds 20 &
NBTV_DEBUG_SETTINGS="callsign=N0CALL;input=BlackHole;output=BlackHole;source=video;mode=12" \
NBTV_DEBUG_VIDEO=影片.mp4 NBTV_DEBUG_SCRIPT="2:tx;9:stop;14:quit" $APP
```

注意：`output=` 找不到符合的裝置時會用系統預設的輸出裝置；測試時不要把訊號送進真的電台。

### 收不到畫面時：查「送出什麼、聽到什麼」

看不出問題在哪一段時，可以讓 app 把音訊與收發的每一步記下來（`Sources/DebugTap.swift`）。
把使用者預設值 `debugTapDirectory` 設成一個目錄，下次啟動 app 生效：

```sh
defaults write tw.hf-nbtv.mac debugTapDirectory -string "$PWD/build-app/tap"    # 第二個 app 是 tw.hf-nbtv.mac2
defaults delete tw.hf-nbtv.mac debugTapDirectory                                # 用完記得關掉
```

目錄裡會有：

| 檔案 | 內容 |
| --- | --- |
| `app1-log.txt`（第二個 app 是 `app2-log.txt`） | 每一步的時間與狀態：啟動時的裝置與設定、按下發射、每一張排入時佇列的狀況、裝置實際取走幾格、同步與解碼的結果。 |
| `app1-tx-時分秒.f32` | 每次發射排進輸出佇列的取樣（乘上輸出音量之前）。 |
| `app1-rx-時分秒.f32` | 每次開始接收後交給接收機的取樣。 |

音訊檔沒有檔頭：32 位元浮點、48 kHz、單聲道，每個檔案最多 15 分鐘。轉成 WAV 就能交給命令列工具：

```sh
sox -t f32 -r 48000 -c 1 build-app/tap/app2-rx-時分秒.f32 -e float -b 32 rx.wav
build/tools/nbtv-rx --trace rx.wav
```

實際遇過的例子：發射端記下來的音訊每一幀都解得回來，接收端記下來的音訊裡卻有一段一段完全是 0 的空白
（每段 10–50 毫秒）。接收用的是 SDR 軟體送進虛擬音效卡的聲音，SDR 接收機以每秒一千萬個取樣的速率、
和螢幕內建的鏡頭共用同一個 USB 2.0 集線器；平常每秒掉一次（約 2% 的時間是空的），鏡頭一開變成每秒七八次
（兩成的時間是空的），而且中間的聲音還少了將近 2%，等於整段被壓短。這種聲音任何模式都解不出來，
SDR 軟體的瀑布圖上則是訊號兩側出現很多「毛邊」。這種情形要處理的是接收的那一段：
SDR 接收機不要和鏡頭共用集線器，或是調低它的取樣率。

## 執行緒

核心的物件不是執行緒安全的，同一個物件只在同一條佇列上使用：

- 即時音訊執行緒只做一件事：在環狀緩衝與裝置之間搬取樣。
- 接收機與頻譜分析在 `RadioEngine` 的序列佇列上（`nbtv_rx_push` 在一幀結束時可能要幾十毫秒，不能放在即時執行緒或主執行緒）。
  解畫面的那一段，核心自己會再用幾條執行緒一起算（2026-11-26 起；見[技術說明](../../docs/TECHNICAL.md)的「畫面編解碼的速度」），
  這條佇列等它算完才往下做。Windows 與 Linux 的桌面 app 把頻譜分析搬到另一條執行緒、來不及時會先不解畫面；這裡還沒有跟著改。
- 發射機在 `AppModel` 的發射佇列上，PTT 在另一條序列佇列上（開序列埠、連線都可能卡一下）。
- 介面的狀態只在主執行緒上改，而且集中在每 0.1 秒一次的更新裡，整個視窗一秒只重排 10 次。

## 已知的限制

- 下拉選單（音訊裝置、序列埠、鏡頭）出現在游標的位置，不是貼齊按鈕。
- 定時發射只有對齊整點的固定間隔與一個影片檔：不能指定只在某幾個小時發射，也不能排好幾個影片輪流播。
  開關不會記住，每次開 app 要自己再打開。到了時間不會先聽頻率上有沒有別種訊號。
- 執行檔只連結系統的函式庫與框架（不再需要 Homebrew 的 libavif）；沒有在別台機器上實際執行過。
- 「輸出裝置停住就自動放開 PTT」的保險是 app 自己在看的：整個 app 沒有回應（卡住）的時候它不會動，那時候只能強制結束 app
  ——用 CAT 指令的話看門的程序會放開 PTT，用自己另外開的 rigctld 則不會（見下一條）。
- 用「Hamlib rigctld（TCP）」（自己另外開的 rigctld）控制 PTT 時，如果 app 當掉或被強制結束（`kill -9`），
  沒有人去送「放開」的指令，電台會停在發射狀態。正常結束、`kill`、Ctrl-C 都會先放開 PTT。
  用「電台的 CAT 指令」那一種的話，app 帶著的看門程序會在 app 不在之後放開 PTT（見上面的 PTT 一節）。
- 用 CAT 指令的 PTT：這台電腦要先裝 Hamlib。送的是 `T 1`，也就是電台預設的發射方式；有些機種把「麥克風」與「資料端子」分成
  兩種發射指令，要用哪一個音源得在電台上設定，app 裡沒有選項。每次發射都重新啟動 rigctld（示範機約 0.2 秒，真的電台要看它回應得多快），
  沒有在發射的時候不佔著序列埠。RTS、DTR 固定壓在低電位，靠這兩條線供電的自製介面不能用這一種，
  請自己開 rigctld、改用「Hamlib rigctld（TCP）」。app 結束的那一刻如果正在等電台回應，要等到逾時（最多十幾秒）才會結束。
- 畫布只有一段字、上緣或下緣兩個位置，字的大小自動決定；不能自己擺位置、換顏色或放圖。
- 圖片序列的順序只能照檔名，不能在 app 裡拖動調整；每一張固定送一次，不能指定某一張重複幾次或停留多久；
  不找子資料夾；看不到整批的縮圖，只看得到下一張要送的那一張。定時發射不能用圖片序列。
  app 會先把下一張讀好；幾千萬像素的 HEIC、JPEG 讀一張不到 0.1 秒，沒有問題，但相機的 RAW 檔要整張解開，
  讀一張要是比送一張還久，下一張會來不及接上，中間空一小段。
- 「在每一張的左上角印上訊雜比」的選項在存影片的對話框裡，不在設定視窗：設定視窗已經和小筆電的螢幕差不多高，再加一列會放不下。
  印的位置與大小固定；存圖片（PNG）時不印。
- 「儲存影片」一次存主畫面那一張所在的一段，沒有進度條、不能取消，存的時候按鈕顯示「儲存中…」。
  影片的時間照畫面收到的時刻排（app 每 0.1 秒整理一次，所以每一張有 0.1 秒左右的誤差）。
- 右側欄多了畫布與輸出音量兩列：視窗縮到最矮（820 點）、來源又是影片檔時，預覽會略為縮小把高度讓出來。
